# 토픽 추출 가이드

입력: `/home/claude/gisulsa/scripts/chunks/chunkN.json` — `[{id, session, text}]` (정보관리기술사 기출 문항)
출력: `/home/claude/gisulsa/scripts/topicwork/topicsN.json` — 입력과 같은 순서·같은 개수의 배열

## 출력 항목

| 필드 | 규칙 |
|---|---|
| `id` | 입력 id 그대로 |
| `title` | 핵심 토픽명. 한글 표기 + 영문/약어가 있으면 괄호. 예: `블록체인(Blockchain)`, `정규화(Normalization)`, `획득가치관리(EVM)`, `RAID` |
| `title_en` | 영문 정식 명칭 또는 약어 (없으면 `""`). 예: `Blockchain`, `Earned Value Management`, `RAID` |
| `domain` | 아래 8코드 중 1개 |
| `sub` | 문항이 토픽의 특정 측면을 묻는 경우 짧게 (예: `삽입 알고리즘`, `보안 이슈`). 없으면 `""` |

## 판단 규칙

- 같은 개념은 회차가 달라도 같은 `title`로 — 표기 통일 (`해시 함수(Hash Function)`를 `해쉬함수`로 쓰지 않기, 영문 대소문자·띄어쓰기 통일)
- 시나리오형 서술 문항: 요구하는 핵심 개념 1개를 title로 (예: 프로젝트 상황 + "EVM 계산" → `획득가치관리(EVM)`)
- 두 개념 비교 문항: `A vs B` 형태 금지 → 상위 개념 또는 주된 개념 하나 (예: 페이징과 세그먼테이션 비교 → `가상 메모리(Virtual Memory)`, sub: `페이징 vs 세그먼테이션`)
- 세부 하위 질문(가·나·다)이 있어도 title은 1개, 세부는 `sub`에
- 코드 작성 문항: 알고리즘/자료구조 이름 (예: `퀵 정렬(Quick Sort)`, `연결 리스트(Linked List)`)
- 법률·제도 문항은 DS, 보안 기술·관리체계는 SEC, 개인정보 "보호기술(비식별화·가명처리)"은 SEC, "법 조항·제도"는 DS
- 통계·확률(가설검정·회귀·표본추출)은 NEW
- 확신이 없으면 가장 가까운 도메인 선택, 빈 값 금지

## 출력 예

```json
[
 {"id":"r139-s1-q01","title":"작업분류체계(WBS)","title_en":"Work Breakdown Structure","domain":"SE","sub":"작성방법"},
 {"id":"r139-s2-q01","title":"AI 리스크(AI Risk)","title_en":"AI Risk","domain":"NEW","sub":"보안·프라이버시·사회적 리스크"}
]
```

반드시 유효한 JSON 파일로 저장. 입력 개수와 출력 개수가 같아야 함.
